# 快速上手

## 这个系统解决什么

三个问题，其余功能都围绕它们：

1. **钱在哪里？** — 各公司、各账户的余额，随流水自动算出来，永远和银行对得上
2. **钱从哪来、到哪去？** — 每一笔收付款都能追到业务单据
3. **未来三个月够不够用？** — 资金预测

## 启动

```bash
cd ~/Develop/gitee/yihu-finance && ./start.sh
```

打开 <http://localhost:5183>。关掉终端服务就停了，下次再跑一遍。

## 账号与权限

| 账号 | 角色 | 能做什么 |
|---|---|---|
| admin | 管理者 | 全部数据 + **付款审批** + 月结锁定 + 用户管理 |
| finance | 财务 | 流水、收付款、工资、报销、发票、月结（**不能审批付款**） |
| staff | 业务 | 提交报销、查看基础资料 |

**审批和付款是分开的两个权限**：财务能执行付款但不能自己审批，管理者能审批但不代财务记账。这是防错，不是麻烦。

## 一条铁律：余额是算出来的，不能手改

```
账户余额 ＝ 期初余额 ＋ 收入 − 支出
```

发现余额不对，**永远是去修因，不是改数字**：要么期初余额不对，要么少记/多记了流水。系统没有"直接改余额"这个功能，就是为了逼出真正的原因。

## 期初余额和期初基准日

每个账户有两个关键字段：

- **期初余额** — 某一天的账面余额
- **期初基准日** — 这个余额是哪一天的

基准日**当天及之前**的所有收支都已经包含在期初余额里了。所以导入早于基准日的流水，余额会重复计算——导入向导会用红字拦你一下。

目前四家账户的期初都按 2026-08-01 的银行对账单口径校准过。

## 名词对照

| 系统里叫 | 意思 |
|---|---|
| 流水 | 银行账户上真实发生的每一笔收支，系统的核心事实 |
| 应收款 | **预计**要收的钱，还没到账，不影响余额 |
| 付款单 | 付款申请，走审批流；审批通过并标记付款后才生成流水 |
| 核对 | 确认这笔流水和银行对账单一致，月结要求全部核对完 |
| 月结 | 锁定某个月，之后该月流水不能再改 |
