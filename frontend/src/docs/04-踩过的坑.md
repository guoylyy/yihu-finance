# 踩过的坑

> 都是真实发生过的，每条后面是当时的处理办法。

## 1. 登记了收款，账户余额没变

**现象**：在「应收与收款」新增了一笔收款，但没让选银行账户，余额也不动。

**原因**：「登记应收款」记的是*预计要收的钱*，不是到账。真正到账要点行末「登记回款」。

**现在**：新增表单底部有「已收到款」开关，勾上就要求选账户，一步完成并生成流水。

## 2. 别处改了数据，这个页面还是旧的

**现象**：登记完回款，切回账户页余额没变。

**原因**：页面被缓存了，切回来不重新请求。

**现在**：所有列表页切回来都会重新加载。如果还是觉得不对，Cmd+R 刷新。

## 3. 账本的"汇总口径"和银行的"逐笔明细"重复记账

**现象**：导入 8 月对账单后，云帆科技余额比银行少 1 万多。

**原因**：系统初始化时从 Markdown 账本搬过来的是**月度汇总**（工资 79,948.09 一笔），而银行明细里是 8-10 的 5 笔「转取」逐笔（合计 81,263.08）。同一笔钱记了两遍。

**处理**：作废汇总口径的那几笔，保留银行逐笔。**以后每月只认银行明细，不要再手工补汇总数。**

## 4. 期初余额是倒推的，和银行对不上

**现象**：四家账户期初都和银行对账单差几千到几万。

**原因**：期初是从 Markdown 账本某天的余额倒推的，账本本身就有误差。

**处理**：期初一律按银行对账单倒推 —— `期初 = 对账单期末余额 + 期间支出 − 期间收入`，基准日设成对账单起始日。

## 5. 作废付款单，流水留了下来

**现象**：误建了工资批次、付了款、又把付款单作废，账上凭空多出一笔 8,639.12 的支出没人认领。

**原因**：作废付款单时没有连带处理它已经生成的流水。

**现在**：作废付款单会一并作废对应流水并重算余额。历史遗留的那笔已手工清掉。

## 6. 账本余额抄错了 50 万

**现象**：拾光云账本写 ¥884,258.00，银行实际 ¥384,258.43。

**原因**：`3` 抄成了 `8`。

**教训**：**以银行对账单为准**，账本数字只做参考。每月对账脚本跑一遍就能发现这类错误。

## 7. 银行导出的文件五花八门

- 农行：有表头，但**末尾有汇总行**（"总收入笔数 / 1 / 20"），曾被当成 2001 年的假流水导进来
- 工行：36 列的对账单，摘要、收付方名称都在很后面
- 某些"明细查询列表"：**完全没有表头**，第一行就是数据
- CSV 编码有 GBK 也有 UTF-8

**现在**：汇总行会被过滤，列名按优先级匹配，没表头的可以手工指定列，编码自动识别。遇到新格式导不进来，先跑一次预览看它认出了什么，再用「手工指定列」纠正。

## 8. 上传的中文文件名存成了乱码

**现象**：导入批次和操作日志里，文件名显示成 `ä»¥èè´¦æ·æç»...xls`。

**原因**：multipart 表单的字段值被按 latin1 解码，UTF-8 的中文就散成了一串拉丁字符。

**处理**：所有上传入口统一做编码还原；历史数据用 `scripts/fix-mojibake-filenames.mjs` 修好了。
日志摘要是"正常中文 + 乱码文件名"混排的，要按乱码片段逐段还原，整串转换会把正常中文也毁掉。

## 9. 付款单挂错公司/账户

**现象**：拾光云的工资批次建在了云帆科技名下，钱从云帆账户出。

**教训**：生成付款单前先确认工资批次的**公司**选对了；标记付款时确认**付款账户**是钱实际出去的那个账户。

## 10. 以虎 One 上 AI 工具报「连不上」，页面却一切正常

- 现象：平台 AI 助手调本系统的工具（资金概况、逾期清单等）全部失败，页面操作正常
- 原因：工具内部用 `callSelf()` 回调本系统接口，没设 `PORT` 时它默认连 3000，而后端默认监听 3010
- 处理：`callSelf()` 默认端口改成和 `index.js` 一致的 3010；以后改默认端口要两处一起改

## 11. 金额经过 Number() 就会悄悄丢分

- 现象：录入助手的草稿里，`999999999999999.99` 变成了 `1000000000000000.00`；`0x10` 被当成 16
- 原因：金额先 `Number()` 再转 Decimal。双精度浮点只能精确表示到 2^53，超过约 90 万亿元的金额，分位就保不住了；`Number()` 还认十六进制和科学计数法
- 处理：金额从字符串直接按正则校验后交给 `Prisma.Decimal`，不经过浮点。以后新写金额解析，一律别用 `Number()` / `parseFloat()`

## 12. 列表按数据范围过滤了，详情 / 修改却没有

- 现象：只能看 A 公司的账号，直接调 `GET/PUT/DELETE /api/fin/invoices/<B 公司发票 id>` 能看能改能作废，`POST` 也能往 B 公司新增
- 原因：`crudRouter()` 和流水接口只在列表里用了 `scopeWhere()`，按 id 操作的接口没校验公司
- 处理：`crudRouter()` 的详情 / 新增 / 修改 / 作废，以及流水的增删改查，都按 `inScope()` 校验。新写按 id 操作的接口时记得一起校验


## 13. `...scopeWhere()` 展开后，又被同名字段覆盖

- 现象：只能看 A 公司的账号，列表接口带上 `?company_id=<B 公司 id>` 就能查到 B 公司的应收、发票、流水、账户（工资、付款计划、月结、资金预测、异常清单、分析图表同理）；
  录入助手里点名「公司 B」或 @ B 公司，草稿的公司会填成 B
- 原因：`scopeWhere(user)` 返回的是 `{ companyId: { in: [...] } }`，展开进 where 后，下一行 `where.companyId = BigInt(company_id)` 把它整个覆盖掉了；
  查公司时的 `{ id: bid, ...scopeWhere(user, 'id') }` 反过来，是范围覆盖了 `id`，变成「范围内任意一家都算存在」。资金预测 / 异常清单 / 分析则是「给了 company_id 就不看范围」
- 处理：范围一律放进 `AND: [scopeWhere(user)]`，和其它筛选条件取交集；SQL 拼接里范围条件始终叠加，不写成 `else`。
  以后写 where 时，凡是会再写 `companyId` / `id` 的，都别直接展开 `scopeWhere()`

## 14. 手机模拟器里「没有横向滚动」，真机上却能左右拖

- 现象：用 playwright / 开发者工具的手机模拟（`isMobile`）跑 `document.body.scrollWidth <= window.innerWidth`，结果是 true，真机上页面却能左右拖
- 原因：移动端浏览器里内容超宽时，布局视口会被撑大，`window.innerWidth` 跟着变成内容宽度（例如 449），拿它比永远相等
- 处理：断言时拿**设定的视口宽度**（375）比，不读 `innerWidth`，见 `frontend/scripts/mobile-audit.mjs`。
  另外，修横向滚动要找到撑宽的元素（脚本会列出来），不要给 `body` 加 `overflow-x: hidden` 盖住
