## 录入助手 E2E

目标不是覆盖率，是「上线后不会出账务事故」：助手不写库、草稿里只有值域内的数据、越权数据进不了草稿、
「确认提交」走的业务接口守得住数据范围、平台故障时降级而不是 500。

### 四种模式

所有命令都在 `backend/` 下执行。

| 模式 | 后端怎么起 | 命令 | 写库？ |
|---|---|---|---|
| **stub 全量**（默认） | `FIN_LLM_STUB=1 npm start` | `node scripts/assistant-e2e.mjs` | 只在测试公司里写，跑完硬删除 |
| **live** | 不设 `FIN_LLM_STUB`，配好 `YH_API_URL` / `YH_CLIENT_ID` / `YH_CLIENT_SECRET` | `node scripts/assistant-e2e.mjs --live` | 同上 |
| **只读**（本地验证冒烟） | stub 起 | `node scripts/assistant-e2e.mjs --read-only` | 不写业务数据（见下） |
| **生产冒烟** | 线上 | `node scripts/assistant-e2e.mjs --read-only --live --base https://<平台>/apps/finance --token <jwt>` | 不写业务数据 |

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--base <url>` | `http://127.0.0.1:3010` | 被测后端（也可用 `E2E_BASE_URL`） |
| `--token <jwt>` | — | 直接用这个身份；不给就用 `--user/--pass` 自动登录 |
| `--user` / `--pass` | `admin` / `admin123` | 自动登录用的账号（也可用 `E2E_ADMIN_USER` / `E2E_ADMIN_PASS`）。平台上默认关了账号密码登录，生产请用 `--token` |
| `--ui <url>` | 同 `--base` | 前端地址（DOM 检查用；默认后端托管的 `frontend/dist`） |
| `--chrome <path>` | macOS 的 Google Chrome | 无头浏览器；找不到就跳过 DOM 检查（标记「跳过」，不算通过） |
| `--only A,F` | 全部 | 只跑某几组（不写报告） |
| `--skip-slow` | 否 | 跳过约 60 秒的「上游超时」检查 |
| `--keep-audit` | 否 | 清理时保留测试产生的审计行 |
| `--report <path>` / `--report none` | `docs/测试报告-录入助手.md` | 结果写进报告里本模式对应的段落（只替换 `<!-- AUTO:… -->` 之间的内容） |
| `--cleanup-stale` | — | 只做一件事：删掉之前跑崩留下的 `E2E-` 测试公司和测试用户 |
| `-v` | — | 打印每次对话的回复与草稿 |

退出码：0 全部通过；1 有失败；2 环境不满足（后端模式和参数不符、连不上库、身份不是 ADMIN 等）。

### 用了哪些账号

- **引导身份**：`--token` 或自动登录的账号（默认 `admin`），**必须是 ADMIN**。它只做两件事：建两家测试公司、建测试用户。
  自动登录会更新这个账号的「最后登录时间」——这是唯一一处碰到既有数据的地方，介意就用 `--token`。
- **测试用户**（每次新建，跑完删除），用户名 `e2e-<时间戳>-<角色>`，随机密码：

  | key | 角色 | 数据范围 |
  |---|---|---|
  | admin / finance / manager / viewer / staff | 各自角色 | 只有两家测试公司 |
  | financeA | FINANCE | 只有测试公司 A |

  所有对话、草稿、提交都用测试用户做，**测试用户的数据范围只有测试公司**，即使测试本身写错了也看不到、改不了真实公司的数据。
- 只读模式不建任何用户，全程用引导身份。

### 测试数据与清理

- 写库模式先建 `E2E-<时间戳36进制>-A` / `-B` 两家公司（排序 9999，排在最后），所有账户、客户、发票、应收、流水都建在这两家下面；
  测试运行期间（约 2 分钟）它们会出现在公司下拉里，跑完即消失。
- 跑完（含失败、Ctrl+C）**硬删除**：按测试公司 id 删流水 → 发票 → 应收 → … → 客户 → 账户 → 公司，按测试用户 id 删用户；
  审计表里删「测试用户的操作」+「引导身份建 / 改测试公司、测试用户的那几行」（`--keep-audit` 可保留）。
  只按 id 删，不按时间段或模糊条件删。
- 建数前、清理后各数一次全部 23 张表的行数写进报告；另按 id 和前缀再查一次「残留测试行」，**残留为 0 才算清干净**。
  测试期间如果有人在录真实数据，行数会正常变化，那不算残留。
- 业务编号（`AR-2026-0007` 这类）按「当前最大号 + 1」生成：测试建的单子删掉后号会空出来，下一笔真实单据会复用——不影响数据，只是号不连续时别奇怪。
- 写库模式要求能直连被测服务的数据库（读 `backend/.env` 的 `DATABASE_URL`），并会核对「刚通过接口建的公司在库里查得到」，确认连的是同一个库，否则中止。
- 跑崩了：`node scripts/assistant-e2e.mjs --cleanup-stale`。

### 只读模式会写什么

只调接口、不建任何数据。但每次 chat 本身会在 `audit_logs` 追加一行 `assistant.chat`（产品行为，只有元信息），
自动登录会更新登录账号的最后登录时间。除此之外不写库。

### 各组在什么模式下跑

| 组 | stub 全量 | live | 只读 |
|---|---|---|---|
| S 冒烟 | ✓ | ✓ | ✓ |
| A 四类草稿 | 断言具体值 | 只断言结构 | — |
| B 修改模式 | ✓ | — | — |
| C 数据范围 | ✓ | 只断言「草稿里没有越权 id」 | — |
| D 权限矩阵 | 五个角色 + DOM | 五个角色 | 只验当前身份 |
| E 降级 | 起子进程后端 + mock 上游（与模式无关，需本机） | 同左 | — |
| F 安全 | 注入 / XSS / 审计 | 注入 / 审计 | 注入（用列表 total 比对）/ 审计 |
| G 边界 | 断言具体值 | 只断言不 500 | 同左 |
| H 幂等并发 | ✓ | 并发 | — |
| I 业务回归 | ✓ | — | — |
| J 性能 | stub 5 次 | live 5 次 | 按模式 |
| K 跨页面 | 断言具体值 + DOM | — | — |

E 组会在本机另起一个后端子进程（随机端口、同一个库、`FIN_LLM_STUB=0`、上游指向脚本内置的 mock），
不影响正在跑的 3010；子进程里 503 之后 5 分钟都报不可用，所以 503 放在 E 组最后。
